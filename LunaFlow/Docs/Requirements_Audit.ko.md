# 요구사항과 구현 점검

검토 기준일: 2026-10-27 (한국 시간)

사용자가 요구사항 자료로 확인한 `LunaFlow_Agent_Plan.pdf` 3쪽과 `LunaFlow_Team_Plan.html`, 현재 소스를 대조했다.
HTML 계획서의 역할별 범위(A 렌더링·재생, B 편집·저장, C AI·FBX 출력)와 공통 데이터 약속(초 단위 시간, 미터·Y-up, 부모 기준 로컬 TRS, 공통 편집 명령)은 아래 성공 기준의 구현으로 확인했다.
계획서에서 모델러의 일이던 리깅과 기준 자세 검증은, 제공된 캐릭터에 뼈대가 없어 자동 리깅 기능으로 보완했다.
계획서 안의 에이전트 지침·답변 예시는 제품 설계 자료로 해석했으며, 개발 작업에 대한 별도 지시로 실행하지 않았다.
기존 [구현 기록](Implementation_Status.md)의 과거 통과 결과와 이번 변경의 최종 검증 결과는 구분한다.

## 계획서의 성공 기준

| 성공 기준 | 확인한 구현 | 상태와 남은 범위 |
|---|---|---|
| 자연어로 새 동작 생성 후 캐릭터 재생 | Copilot Studio SDK 연결, 장면·뼈·현재 자세 문맥, `create_motion`과 뼈 키 편집, 계획 검증, 단계별 반영과 재생 | 기본 클립 생성·수정 경로는 있다. 외부 전신 모션 생성 API는 연결되어 있지 않다. AI가 임의의 뼈 로컬 회전을 추측하면 의도와 반대로 움직일 수 있어, 방향이 검증된 동작 명령이 필요하다. |
| “두 배 빠르게” 요청이 키 시간과 동작 길이를 함께 변경 | `retime_motion` → `RetimeClip`: 모든 위치·회전·크기 키 시간에 같은 배율을 적용하고 길이를 변경 | 구현됨. `CoreTests.cpp`에서 길이 변경과 키 시간·재생 속도를 검사한다. |
| 직접 편집한 키가 재생·저장·복원에 반영 | 타임라인 키 추가·교체·시간 이동·삭제, 수치·기즈모 편집, `EvaluatePose`, `.lunaflow` 전체 프로젝트 저장 | 구현됨. 전체 프로젝트 저장과 현재 동작 JSON 저장을 구분한다. 저장 실패·취소 시 변경 상태를 유지한다. |
| 여러 동작을 FBX로 내보내 Unity에서 개별 재생 | 모든 클립을 별도 Take로 샘플링하는 FBX 출력, Unity Generic 가져오기, Animator Controller와 프리팹 생성 | FBX 왕복과 Unity 어셈블리 C# 컴파일 검증 경로가 있다. 실제 Unity Editor 가져오기·Play 모드 검증은 활성 라이선스가 필요하며 아직 완료되지 않았다. |
| 실패 시 기존 작업 보존과 이유 표시 | 전체 계획을 사본에서 사전 검사, 세션·revision·뼈대·장면 변경 검사, 단계별 사본 적용, 오류 메시지, AI 작업 단위 Undo·중지 | 구현됨. 전체 계획의 구조 오류는 반영 전에 거부한다. 실행 중 사용자가 장면을 변경하면 남은 단계를 중지하고 이미 적용된 단계는 Undo할 수 있다. |

계획서의 Blender 내보내기 경로는 현재 네이티브 FBX 출력으로 구현되어 Blender 설치가 필요 없다.
계획서의 3주 시제품에서는 VFX를 제외했으나 현재 프로젝트에는 직접 편집·로컬 프롬프트·AI 계획을 통한 파티클 제작 기능도 있다.

## UX 기준

Unity의 [Scene view navigation](https://docs.unity.com/en-us/engine/6000.6/manual/unity-editor/editor-windows-views-reference/using-the-scene-view/scene-view-navigation)은 우클릭+WASD·Q/E 탐색과 Shift 가속을 제공한다.
Blender의 [Continuous Grab](https://docs.blender.org/manual/en/latest/editors/preferences/input.html)은 커서를 뷰 안에서 이동시켜 화면 경계에 따른 조작 제한을 없앤다.
현재 편집기의 도구와 단축키를 유지하면서 이 두 조작을 적용했다. Unity의 Alt 조작·F 맞추기·Scene Gizmo·K 키 추가와 Blender의 숫자패드 시점·원근/직교 전환·I 키 추가를 함께 반영하고, F1 단축키 목록·뷰포트 안 안내·README 단축키 표를 같은 내용으로 맞췄다.

## 남은 제품 범위

- 외부 전신 모션 생성 API, 걷기·인사 등 전신 동작의 품질 검증된 생성 라이브러리는 아직 없다.
- FBX 체형 보정은 이름·전체 경로 기반 매칭, 기준 자세·키·뼈 길이 보정, 인식된 손발 체인의 IK를 지원한다. 임의 이름의 수동 뼈 매핑·임의 구조의 완전 자동 리타기팅은 남아 있다.
- 관통 검사는 관절 위치와 몸통 근사 형태를 사용한다. 메시 전체 충돌이나 물리 기반 균형을 해결하지 않는다.
- 자동 리깅은 서 있는 사람형 캐릭터용이다. 손가락·얼굴·옷자락 뼈는 만들지 않으며, 팔이 몸에 붙은 모델은 겨드랑이 부분이 팔을 크게 들 때 늘어날 수 있다. 로브를 입고 손이 옷자락에 붙은 I 자세처럼 팔·다리·목이 구분되지 않는 모델은 거부한다.
- Unity 내부 가져오기·각 클립 재생은 별도 검증이 필요하다. 검 모션은 자동 리깅한 기본 캐릭터와 Mixamo 이름 리그에서 검사했으며, 다른 사용자 리그에서의 품질은 추가 확인이 필요하다.
- 실제 웹캠·사람의 모션캡처 품질, Copilot Studio에 게시한 VFX 전용 에이전트의 실제 대화, 이 PC Unity Editor에서의 `LunaFlow-Unity` 가져오기는 사용자 설치·로그인 후 확인이 필요하다.
- 현재 문서의 “AI UI만 제공”, “모든 자동 리타기팅 미지원” 설명은 실제 코드와 달라 이번 점검에서 바로잡았다.
