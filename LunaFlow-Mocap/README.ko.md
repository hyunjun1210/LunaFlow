# LunaFlow 웹캠 모션캡처

이 폴더는 LunaFlow에 병합되어 있습니다. 루트 `CMakeLists.txt`가 `Mocap.cmake`를 포함하고,
편집기 연결(보기 메뉴, 캡처 중 편집 잠금, 창 닫기 처리, 녹화 테이크 Undo)은 기존 `LunaFlow\App` 소스에 직접 반영했습니다.

## 구현 범위

- 로컬 USB/내장 웹캠 → OpenCV → MediaPipe Pose Landmarker Lite → 익명 파이프 → C++ 뼈 회전 → 기존 DX11 뷰포트.
- 정면·제자리 1인 전신 동작. 기본 캐릭터(자동 리깅된 FBX)와 리깅 예제 캐릭터를 바로 지원. 원버튼 녹화(카메라 자동 켜기, 기준 자세 자동 보정, 카운트다운·자동 정지), 회전 평활화, 30 FPS 녹화 후 키 자동 정리, 새로운 `AnimationClip` 즉시 적용·트림.
- 기존 동작은 수정하지 않습니다. 완료한 동작은 기존 타임라인에서 재생/키 편집하고 `.lunaflow`, 동작 JSON, 기존 Unity/FBX 내보내기를 그대로 사용합니다.
- 손가락·표정·개별 머리 회전·손목 회전·발 회전·팔다리 축 비틀림·발 고정 IK·정확한 공간 이동은 구현하지 않습니다. 손/머리/발은 부모를 따르는 바인드 회전입니다. 엉덩이/루트 위치는 고정합니다.
- 단안 영상의 깊이는 추정치입니다. 전신 가림, 옆/뒤로 회전, 빠른 동작, 헐렁한 옷, 조명, 카메라 화각에 따라 품질이 달라집니다. 전문 모션캡처 품질을 보장하지 않습니다.

## 설치

Windows x64, LunaFlow의 기존 C++17/VS 2022/CMake 환경, **Python 3.11 x64 + Python launcher (`py`)**, Git for Windows가 필요합니다.
`mediapipe==0.10.21`에는 CPython 3.11용 Windows x64 wheel이 있습니다. 이 버전 조합은 Python 3.13용이 아닙니다.
다른 Python 환경을 변경하지 않고 이 폴더의 `.venv`에 설치합니다.

모델 출처와 이용 조건의 확인 범위는 [THIRD_PARTY.md](THIRD_PARTY.md)를 먼저 읽으세요.

```powershell
# 프로젝트 루트에서 실행. 패키지/모델 다운로드 시에만 인터넷 필요.
powershell -NoProfile -File .\LunaFlow-Mocap\Setup.ps1 -SmokeTest
.\Build-LunaFlow.ps1 -Configuration Release -Test
```

`-SmokeTest`는 검은 이미지에 실제 추론을 실행할 뿐 웹캠을 켜지 않습니다. 사람 자세 정확도 검사는 아닙니다.
앱의 모션캡처 패널에서 **설치하고 카메라 켜기**를 누르면 같은 `Setup.ps1`을 앱 안에서 실행하고 진행 단계를 보여 준 뒤 카메라를 켭니다(취소·다시 시도 가능).
`Setup.ps1 -SkipModel`로 의존성만 준비할 수 있습니다. 모델은 공식 버전 URL에서 내려받아
`LunaFlow-Mocap\Models\pose_landmarker_lite.task`에 놓고 문서의 SHA256과 일치해야 합니다.
기존 모델 해시가 다르면 자동 덮어쓰기하지 않습니다. 원인을 확인한 뒤 올바른 버전을 별도로 준비하세요.

**최종 검증에서 전용 환경 설치, 의존성 검사 및 실제 모델의 빈 이미지 추론이 통과했습니다. 실제 사람의 웹캠 동작 품질은 아직 별도 확인이 필요합니다.**
네이티브 앱 빌드, 가상 관절/가상 프로세스, 저장/내보내기 검증과 구분한 결과는 [VALIDATION.ko.md](VALIDATION.ko.md)에 있습니다.

## 사용 순서 (원버튼 녹화)

Unity Animation 창의 녹화 버튼처럼 **카메라 켜기 → 녹화 → 확인** 세 단계로 끝납니다.

1. 타임라인 맨 왼쪽의 빨간 **녹화(●)** 버튼이나 `보기 > 웹캠 모션캡처...`를 누릅니다. 설치가 되어 있으면 패널이 열리면서 **카메라가 바로 켜집니다.**
   설치 전이면 **설치하고 카메라 켜기** 한 번으로 `Setup.ps1`이 앱 안에서 실행되고(4단계 진행 표시·취소 가능) 끝나면 카메라가 켜집니다.
2. 밝은 곳에서 머리부터 발끝까지 보이게 섭니다. 패널의 미리보기 실루엣과 체크리스트(카메라 → 전신 보이기 → 기준 자세 → 녹화 준비)가
   "한 걸음 뒤로", "왼쪽으로 조금" 같은 안내를 보여 줍니다.
3. 정면을 보고 팔을 내린 채 잠깐(0.75초, 15프레임) 멈추면 **기준 자세가 자동으로 잡힙니다.** 따로 캘리브레이션 버튼을 누를 필요가 없습니다.
   카메라 위치가 바뀌면 **기준 자세 다시 잡기**를 누르세요.
4. **녹화** 버튼 또는 **Space**. 기본 3초 카운트다운(없음/3/5/10초)이 뷰포트 가운데에 표시되고, 몸이 화면을 벗어나 있으면 돌아올 때까지 카운트다운이 멈춰 기다립니다.
   녹화 중에는 뷰포트에 빨간 테두리와 `REC 00:03.2`가 표시됩니다. 자동 정지(5/10/30/60초)를 고르면 손을 쓰지 않고 끝낼 수 있습니다.
5. **정지** 또는 **Space**. 테이크가 **즉시 새 동작으로 캐릭터에 적용**되고 뷰포트에서 반복 재생됩니다. 카메라는 켜진 채로 남습니다.
   - **계속 녹화 (Space)**: 이 테이크를 유지하고 바로 다음 테이크를 녹화
   - **버리기 (Del)**: 테이크와 그 Undo 기록을 지움
   - **완료 (Enter)**: 테이크를 유지하고 카메라를 끔
   - 시작/끝 슬라이더로 앞뒤의 준비 동작을 잘라낼 수 있습니다(완료·계속 녹화 시 적용).
6. 테이크 이름은 비워 두면 `웹캠 녹화 1, 2...`로 자동으로 붙습니다. 각 테이크는 Ctrl+Z 한 번으로 되돌릴 수 있고, **Ctrl+S**로 프로젝트에 저장합니다.

**키프레임 자동 정리**(기본 켜짐, 허용 오차 1°)가 30 FPS로 찍힌 키 중 보간으로 되살릴 수 있는 키를 지워, 리뷰 카드에 `키 1380 -> 60`처럼 표시합니다.
잘못 잡힌 구간은 타임라인에서 바로 키를 지우거나 고치면 됩니다. 고급 설정에서 카메라 번호(0~15), 떨림 보정(기본 0.09초), 자동 정리와 허용 오차, 기능 폴더를 바꿀 수 있습니다.

좌우는 사용자의 **해부학적 좌우**입니다. 영상 입력을 좌우 반전하지 않습니다. 사용자 오른팔은 캐릭터의 `RightUpperArm`으로 연결됩니다.
영상 자체는 저장하지 않으며 패널에는 관절 실루엣만 표시합니다. 카메라가 켜진 동안 메뉴·라이브러리·속성·타임라인 편집, 기즈모·뼈 선택이 잠기고 기존 AI 작업은 중단됩니다.
단축키는 녹화용(Space 녹화/정지, Esc 카운트다운 취소, Enter 완료, Del 버리기)으로 바뀝니다. 뷰포트 카메라 이동(우클릭 궤도/WASD, 휠, 중클릭 이동)은 계속 사용할 수 있습니다. 카메라를 끄면 편집이 복구됩니다.

## 추적 손실과 카메라 해제

- 필수 관절의 visibility/presence가 0.6 미만이거나 화면 밖이면 **전신 자세를 마지막 값으로 유지**하고 경고합니다. 일부 관절만 임의로 움직이지 않습니다.
- 0.5초 이내의 짧은 누락은 다음 유효 포즈까지 보간합니다. 0.5초를 넘는 손실/시간 간격은 **마지막 유효 관측까지만** 새 클립으로 끝냅니다. 누락된 구간을 정상 추적으로 꾸며서 녹화하지 않습니다.
- UI/추론 속도가 달라도 추적 시점의 단조 증가 타임스탬프로 키를 30 FPS 재샘플링합니다. 렌더 프레임 수를 녹화 시간으로 사용하지 않습니다.
- UI 정지로 큐가 120개를 초과하면 명시적 오류와 함께 종료합니다. 오래된 프레임을 무제한 쌓지 않습니다.
- 종료 요청은 UI를 기다리게 하지 않고 worker에 보냅니다. Python은 카메라를 소유한 스레드의 `finally`에서 `release()`합니다. 드라이버가 막히면 최대 3초 후 **LunaFlow가 만든 해당 worker/job만** 종료하고 경고합니다. 다른 앱/카메라 프로세스는 건드리지 않습니다.
- 앱 닫기 시 먼저 카메라를 종료하고 녹화분을 새 동작으로 만든 뒤 기존 미저장 변경 확인을 사용합니다. 예기치 않은 OS/앱 강제 종료 시 아직 저장하지 않은 클립은 복구되지 않습니다.

## FBX 지원을 과장하지 않습니다

검증된 기준은 기본 캐릭터의 자동 리그, 리깅 예제 캐릭터(14-node rig)와 그에 대응하는 합성 리그입니다. FBX는 다음 **이름/계층/좌표 조건을 통과한 경우만** 연결합니다. 모든 humanoid/모든 Mixamo 파일의 호환성을 뜻하지 않습니다.

필수 고유 이름: `Hips`, `Chest`, `Head`, `LeftUpperArm`, `LeftForeArm`, `LeftHand`,
`RightUpperArm`, `RightForeArm`, `RightHand`, `LeftUpperLeg`, `LeftLowerLeg`, `RightUpperLeg`, `RightLowerLeg`.
namespace 접두사(`mixamorig:` 등)는 제거하고 `Spine2→Chest`, `Left/RightArm→Left/RightUpperArm`,
`Left/RightUpLeg→Left/RightUpperLeg`, `Left/RightLeg→Left/RightLowerLeg`만 별칭으로 처리합니다.

흉부/머리는 엉덩이의 자손, 팔은 흉부의 자손, 다리는 엉덩이의 자손이며 upper→lower→hand/foot 순서여야 합니다.
종아리에 자식이 있으면 고유한 `LeftFoot`/`RightFoot` endpoint가 필요하며, 리깅 예제 캐릭터처럼 leaf 종아리면 허벅지 축을 사용합니다.
`+Y` 위, 해부학적 왼쪽 `+X`, 캐릭터 정면 `-Z`(LunaFlow의 왼손 좌표계)가 전제입니다. 병합 시 다른 PC 버전의 `-X` 전제를 현재 리그의 좌우 규약에 맞게 바꿨습니다. 메시가 향하는 정면은 이름만으로 확인할 수 없으므로 사용자가 확인해야 합니다.
양수 균일 scale만 허용하고 중복 이름/잘못된 계층/0길이/반사·비균일 scale은 시작 시 이유와 함께 거부합니다.
T/A bind 자세의 팔 방향은 측정 방향에 맞추지만 twist/보조 뼈 해석은 하지 않습니다. 회전을 기록하는 것은 10개 몸통/팔다리 뼈뿐이며 다른 노드는 바인드 로컬 변환을 유지합니다.
조건을 만족하지 않는 FBX는 수동 매핑 UI가 아직 없으므로 자동 리깅(`편집 > 캐릭터 자동 리깅`)으로 표준 이름 리그를 만든 뒤 사용하세요.

## 개인정보 / 네트워크

촬영 영상은 추론용 프로세스 메모리에만 존재합니다. 파일 저장/외부 업로드/LLM/Copilot Studio 호출은 없습니다.
앱으로 전달되는 것은 33개 관절의 추정 좌표·confidence·정규화 화면 좌표와 상태 메시지뿐입니다.
프로세스 간 통신은 부모가 생성한 익명 파이프이며 TCP/UDP 포트를 열지 않습니다.
의존성/모델을 준비한 뒤 캡처에는 네트워크가 필요하지 않습니다. 원본 영상, 모델, `.venv`, 계정 설정은 이동 ZIP에 포함하지 않습니다.
