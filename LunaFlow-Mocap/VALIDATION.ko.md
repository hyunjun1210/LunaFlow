# 검증 범위와 남은 확인

## 자동 검증

2026-10-29, Windows x64 / VS 2022 / C++17 Release에서 기존 `build\Release\LunaFlow.exe`를 정상 경로로 다시 빌드했습니다.
Interactive 모드의 실제 도구 승인 후 최종 검증을 재개했고, 다음 CTest **6개가 모두 통과**했습니다.

| 검사 | 확인한 내용 |
|---|---|
| `LunaFlow.CoreAndDX11` | 기존 코어/DirectX11 경로 회귀 |
| `LunaFlow.UiLayout` | 기존 편집 UI/레이아웃 회귀 |
| `LunaFlow.VfxAgent` | 기존 VFX 에이전트 회귀 |
| `LunaFlow.Mocap` | 엄격한 패킷 형식/순서, 캘리브레이션, 가림, 좌우/깊이/부모 회전, T-bind 대응, 지원하지 않는 리그 거부, 시간 기반 30 FPS 키 생성/120초 제한, 추적 중단 시 유효 구간 보존, JSON/프로젝트 저장·재생·키 수정, 기존 Unity 패키지 내보내기, 편집기 새 클립 연결, 가상 Python worker의 정상 종료/오류/강제 정리 |
| `LunaFlow.MocapTracker` | Python 표준 라이브러리만 사용하는 6개 검사: 패킷/NaN/신뢰도, stdin stop/EOF, 카메라 연결 해제 시 release, 최신 프레임 슬롯/단조 타임스탬프 |
| `LunaFlow.MocapModelSmoke` | 전용 Python 3.11 프로세스에서 실제 MediaPipe Lite 모델을 로드하고 빈 이미지 추론 → 네이티브 익명 파이프 → `ready`/`detected:false`/`stopped` 파싱 및 소유 프로세스 종료까지 확인. 웹캠 미사용 |

`LunaFlow.Mocap`의 프로세스 검사는 카메라를 열지 않는 `Tests\fake_tracker.py`를 사용합니다.
Python이 CMake에서 발견되지 않으면 해당 부분과 Python CTest가 생략되므로 구성 출력과 CTest 목록을 확인해야 합니다.
개발 환경에서는 Python이 발견되었고 가상 프로세스 검사까지 실행했습니다.
모델 smoke CTest는 `.venv\Scripts\python.exe`와 모델이 존재할 때 CMake 재구성 시 등록됩니다.
`Setup.ps1 -SmokeTest`로 실제 의존성을 설치하고 `pip check`가 `No broken requirements found.`를 반환한 것도 확인했습니다.
검증된 직접 의존성은 MediaPipe 0.10.21, OpenCV contrib 4.11.0.86, NumPy 1.26.4이며 Python 3.11 x64 전용 환경만 사용했습니다.
별도 standalone 추론과 네이티브 IPC 추론 모두 검은 이미지에 대해 정상적인 미검출 결과를 반환했습니다.

### 현재 프로젝트 병합 후 재검증

전송용 ZIP/패치 대신 편집기 연결을 현재 소스에 직접 반영했습니다. Release 빌드 경고 0개, CTest 6개
(`CoreAndDX11`, `UiLayout`, `DefaultCharacter`, `VfxAgent`, `Mocap`, `MocapTracker`)가 모두 통과했습니다.
모델 smoke는 이 PC에서 `Setup.ps1`을 아직 실행하지 않아 등록되지 않았습니다.

- 좌표계: 현재 리그(해부학적 왼쪽 `+X`)에 맞춰 MediaPipe 좌표 변환과 캘리브레이션/바인드 검사를 수정하고 검사 기대값을 갱신했습니다.
- 기본 캐릭터: 자동 리깅된 FBX 기본 캐릭터에서 구성·캘리브레이션, 오른팔을 들면 캐릭터 오른쪽(`-X`)으로 올라가는지,
  1초 녹화(10개 트랙) → `.lunaflow` 저장 → 다시 열기까지 검사합니다. 저장 파일은 Unity importer 계약 검사도 통과했습니다.
- 편집기: 캡처 중 편집 잠금(뷰포트 카메라 이동은 허용), 장면 교체 차단, 녹화 테이크 추가의 Undo를 반영했습니다.

## 아직 검증하지 못한 것

- **실제 웹캠/실제 사람:** 카메라를 임의로 켜지 않았습니다. 포즈 정확도, 지연, 특정 장치 드라이버의 실제 release 동작은 사람이 참여하는 검증이 필요합니다.
- **실제 다양한 FBX와 Unity 실행:** 지원 이름/계층을 갖춘 합성 리그 및 기존 내보내기 파일 생성은 검사했지만 모든 FBX/Unity 버전에서 실제 캐릭터를 플레이한 것은 아닙니다.
- 모델 가중치의 명시적인 라이선스는 `THIRD_PARTY.md`의 미확인 사항을 참고하세요.

가상 데이터 검사 통과를 실제 모델의 사람 추적 품질 검증으로 해석하지 마세요.

## 설치 후 사람이 확인할 순서

1. `Setup.ps1 -SmokeTest`를 실행합니다. `ready`, 빈 이미지 결과(`detected:false`), `stopped`가 출력되는지 확인합니다. 모델 해시가 다르면 진행하지 않습니다.
2. 기본 캐릭터에서 카메라를 시작하고 전신이 보이는 정면 자세로 캘리브레이션합니다. 팔을 내린 기준 자세가 비틀어지지 않는지 확인합니다.
3. **본인의 오른팔만** 들었을 때 캐릭터의 오른팔만 들리는지, 팔을 카메라로 내밀 때 정면 방향으로 움직이는지 확인합니다. 팔 굽힘/다리 들기/몸통 기울이기를 천천히 각각 확인합니다.
4. 5~10초 녹화 후 종료합니다. 기존 Wave/Idle/Walk가 그대로 있고 새 클립의 길이/방향/재생/키 수정이 맞는지 확인합니다.
5. 녹화 중 손목/발목을 잠시 가린 뒤 0.5초 이상 가립니다. 경고, 자세 유지, 유효 구간으로 종료, 카메라 해제, 새 클립 보존을 확인합니다.
6. 녹화 중 카메라를 분리하고 앱을 닫는 경우도 확인합니다. 다른 앱 프로세스를 건드리지 않고 오류가 표시되며 종료/미저장 확인으로 이어져야 합니다. 녹화 중 강제 OS 종료는 복구 대상이 아닙니다.
7. `.lunaflow`로 저장하고 다시 열어 새 클립을 재생합니다. 현재 동작 JSON과 기존 Unity 패키지를 내보내고 기존 importer로 가져옵니다. Unity에서 같은 뼈 방향/길이/키가 유지되는지 확인합니다.
8. 카메라 종료 후 Windows 카메라 앱에서 장치를 열어 자원 해제를 확인합니다. 12~30 FPS 추론/60 FPS 렌더처럼 속도가 달라도 녹화 재생 길이가 실제 관측 시간과 일치하는지 확인합니다.

실제 장치에서 동작이 잘못되면 문제 클립/리그 이름/카메라 번호/패널의 상태 메시지를 확인하되, 원본 사용자 영상을 외부 서비스에 자동 전송하지 마세요.
