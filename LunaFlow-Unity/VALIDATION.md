# 검증 기록

검증일: 2026-10-28. Unity **6000.3.5f2**, Windows, Built-in Render Pipeline, Direct3D 11. 사용자 라이선스를 정상 확인한 Editor에서 독립 프로젝트로 실행했습니다.

## 통과

- 실제 Unity 가져오기와 Play 모드: **37개 검사 통과**. `Tools~/UnityVerification.cs`로 재현합니다.
- 파일 계약/잘못된 데이터/샘플링: **18개 검사 통과**. `Tools~/ContractTests.cs`로 재현합니다.
- 패키지 코드 및 Unity 검증 도구 C# 컴파일: **경고 0개, 오류 0개**. Unity 6000.3.5f2와 6000.3.19f1의 참조 어셈블리를 사용했습니다.

Unity 검사는 프리팹 생성, 메타데이터, Generic Avatar, 여러 메시, 메시별 스킨 인덱스, DirectX inverse-bind 변환, 원시 RGBA 및 UV 방향, 속도가 반영된 회전, 뼈 계층, CPU 스키닝 결과를 확인했습니다. 동작 전환 후 기준 자세 복원, 파티클의 뼈 부착과 시간/동작 활성화, 재가져오기 시 AnimationClip 참조 유지, VFX 가져오기 해제도 확인했습니다.

Play 모드에서는 기본 동작 자동 재생, 시간 경과에 따른 뼈 회전과 파티클 생성, 시간 이동 후 정지 자세 유지, 계속 재생, 다른 동작으로 전환할 때 자세 및 VFX 초기화를 검사했습니다. 실제 Play 프레임에서 동작 전후 이미지를 렌더링해 확인했습니다.

입력 파일은 작은 내장 샘플과 기존 C++ 에디터의 저장 파일 `Tools~/Fixtures/EditorSnapshot.lunaflow`를 사용했습니다. 후자는 뼈 14개, 메시 17개, 동작 4개, 파티클 1개를 포함합니다. 두 파일 모두 부모 소스 폴더 없이 읽을 수 있습니다.

## 아직 검증하지 않은 환경

URP/HDRP 실행, Unity 6.0 Editor 실행, 모바일/콘솔 및 IL2CPP 빌드는 미검증입니다. Humanoid 변환, 자동 리타기팅, 세계 좌표 파티클의 과거 궤적 복원은 구현 범위에 포함되지 않습니다.

이 PC의 Unity 6000.3.19f1에서는 별도로 컴파일 보조 프로세스 실행에 Windows `GetLastError: 5`가 발생했습니다. 해당 버전의 실제 가져오기 검증은 완료하지 못했고, 6000.3.5f2에서 37개 통합 검사를 완료했습니다. 라이선스 활성화 문제와는 별개의 오류입니다.
